# Memory Manager — Stages 1-3 Implementation

## What was built
- `src/memory/taxonomy_loader.py` — taxonomy load + validation
- `src/memory/embedder.py` — dense/sparse/LI embeddings via LiteLLM + FastEmbed
- `src/memory/qdrant_client.py` — Qdrant collection management + upsert

## Key decisions
- Module-level singleton pattern for QdrantClient, Embedder, and taxonomy cache
- Embedding models are lazy-init (module-level, shared across all Embedder instances)
- Error classes per spec §7 hierarchy (ClassificationError, EmbeddingError, QdrantError)

## Items flagged for future investigation
1. **Embedding batching efficiency** — `Embedder.embed()` currently processes one text at a time. Should support batch embedding (list of texts) to reduce LiteLLM/FastEmbed overhead.
2. **Qdrant upload method selection** — Need to verify effectiveness of `upload_point` vs `upload_points` vs `upsert_point` vs `upsert_points` and use the most efficient option. General principle: more complex schema manipulation and fewer LLM calls are more effective.

## What was assumed
- `docs/rag-dev/taxonomy-schema.json` exists relative to project root (cwd)
- Qdrant is reachable at `QDRANT_HOST:QDRANT_PORT` defaults (`qdrant:6333`)
- LiteLLM is reachable at `LITE_LLM_URL` default (`http://litellm:4000`)
