## Items flagged for future work (from Stages 1-3 + user direction)
1. **Embedding batching efficiency** — `Embedder.embed()` currently processes one text at a time. Should support batch embedding (list of texts) to reduce LiteLLM/FastEmbed overhead.
2. **Qdrant upload method selection** — Verify `upload_point` vs `upload_points` vs `upsert_point` vs `upsert_points` and use the most efficient option. General principle: more complex schema manipulation and fewer LLM calls are more effective.
3. **Test data for live system** — Need to create accurate test data that exercises the live system. Should include:
   - Content across all 4 category_types (knowledge, objective, learning, thought)
   - Various subcategories within each type
   - Tags that exist in the taxonomy
   - Both pre-classified (skip LLM) and unclassified (use LLM) inputs
   - Edge cases: empty tags, content near boundaries
   - Verify round-trip: ingest → verify chunk_id returned → search Qdrant to confirm point exists
